# Button

A button triggers an **action** in the current screen: save, submit, approve, delete. Every variant meets WCAG AA
contrast in the light, dark and high-contrast themes.

**Component:** MGS-owned, built on RSuite 6.2.4 `Button` · Related:
[IconButton](?path=/docs/components-iconbutton--docs) (icon only),
[ButtonGroup and ButtonToolbar](?path=/docs/components-buttongroup--docs) (grouping),
[Icons](?path=/story/foundation-icons--gallery)

## When to use

- To start an action: submit a form, save, create, approve, delete, export.
- **Not for navigation.** If clicking it opens another page, use a link: links can be opened in a new tab, and screen
  readers announce them as links.
- **Not for an icon without a label.** Use [IconButton](?path=/docs/components-iconbutton--docs), which requires an
  accessible name.

## Import

```tsx
import { Button } from '@mgs/ui';
import '@mgs/ui/styles.css'; // once, in your app entry
```

## Usage

```tsx
<Button variant="primary" onClick={save}>
  Save
</Button>
```

## Examples

Every example is also a story in the sidebar, where you can interact with it.

### Basic

<Canvas of={ButtonStories.Basic} sourceState="shown" />

`type` defaults to `"button"`, so a Button never submits a form by accident. Use `type="submit"` for the form's main
action.

### Variants

<Canvas of={ButtonStories.Variants} sourceState="shown" />

| `variant`             | Use it for                                                   |
| --------------------- | ------------------------------------------------------------ |
| `primary`             | The single most important action in a view: _Save_, _Create_ |
| `secondary` (default) | Normal actions: _Cancel_, _Export_, _Edit_                   |
| `danger`              | Destructive actions: _Delete_, _Remove_                      |
| `ghost`               | Secondary actions that need an outline, on busy backgrounds  |
| `link`                | Low-emphasis actions that should look like inline text       |

### States

<Canvas of={ButtonStories.States} sourceState="shown" />

The states you set are `disabled` and `loading`; hover, pressed and focus follow the pointer and keyboard. Each state
is exposed to CSS as `data-disabled` / `data-loading`, next to `data-variant` and `data-size`.

### Sizes

<Canvas of={ButtonStories.Sizes} sourceState="shown" />

`size`: `sm | md` (default) `| lg`. Match the size of the inputs next to the button. Inside a `ButtonGroup`, set
`size` on the group.

### Loading

<Canvas of={ButtonStories.Loading} sourceState="shown" />

`loading` shows a spinner while an action runs. The button keeps its width, its accessible name and keyboard focus,
sets `aria-busy`, and ignores clicks, Enter and Space: `onClick` doesn't run and a submit button doesn't submit again.

### Disabled

<Canvas of={ButtonStories.Disabled} sourceState="shown" />

A disabled button can't be focused or clicked, and users can't find out why. Prefer an enabled button that explains
what's missing when clicked.

### Advanced examples

<Canvas of={ButtonStories.Advanced} sourceState="shown" />

A page header with one primary action, and a form whose submit button is busy while saving.

⚠️ **Edge case: labels don't wrap.** A label wider than its button is cut off at both ends, with no ellipsis, as the
last row shows. Screen readers still read the full label, but sighted users don't see it. Keep labels short (one to
three words) and don't put buttons in columns narrower than their label.

## Do and don't

| Do                                                           | Don't                                                              |
| ------------------------------------------------------------ | ------------------------------------------------------------------ |
| Use one `primary` button per view or dialog                  | Put two primary buttons next to each other                         |
| Write labels as verb + noun: _Save order_, _Approve invoice_ | Write vague labels: _OK_, _Submit_, _Click here_                   |
| Use `loading` while an action runs                           | Use `disabled` while loading (focus is lost) or add your own guard |
| Use `danger` for destructive actions, and confirm them first | Use `danger` for emphasis or colour                                |
| Explain why an action is unavailable when it's clicked       | Disable a button without telling the user why                      |
| Use a link for navigation                                    | Use `onClick` to change pages                                      |

## ERP usage

- **Forms:** Cancel (`secondary`) then Save (`primary`, `type="submit"`, `loading` while saving), aligned to the end
  of the form.
- **Page headers:** the main action (_New order_) as `primary` with `leftIcon={<PlusIcon />}`; others (_Export_,
  _Import_) as `secondary`.
- **Dialogs:** the confirming action is `primary`, or `danger` for destructive confirmations (_Delete 3 invoices_).
- **Tables and toolbars:** use `size="sm"`; for row actions use [IconButton](?path=/docs/components-iconbutton--docs).
- **Bulk actions:** include the count in the label (_Approve 12 invoices_).

## Accessibility

<Canvas of={ButtonStories.Accessibility} sourceState="shown" />

| Key               | Action                                   |
| ----------------- | ---------------------------------------- |
| `Tab` / `⇧ Tab`   | Move focus to the next / previous button |
| `Enter` / `Space` | Activate the focused button              |

- Renders a native `<button>`, so keyboard, forms and screen readers work out of the box. The label is the accessible
  name.
- The focus ring shows for keyboard focus only, drawn **outside** the button with `outline`: visible on every variant
  and in Windows High Contrast mode.
- `loading` sets `aria-busy` and keeps focus; `disabled` removes the button from the tab order.
- Contrast, text on fill, default / hover / pressed:

  | Variant     | Light             | Dark              | High contrast      |
  | ----------- | ----------------- | ----------------- | ------------------ |
  | `primary`   | 5.2 / 6.7 / 8.7   | 5.2 / 6.7 / 8.7   | 17.3 / 17.0 / 17.1 |
  | `secondary` | 11.6 / 9.9 / 13.3 | 8.9 / 5.3 / 5.1   | 17.3 / 17.0 / 17.1 |
  | `danger`    | 4.8 / 6.5 / 8.3   | 4.8 / 6.5 / 8.3   | 7.8 / 6.8 / 5.0    |
  | `ghost`     | 8.7 / 10.4 / 14.7 | 7.3 / 10.3 / 15.3 | 17.3 / 17.0 / 17.1 |
  | `link`      | 8.7 / 10.4 / 14.7 | 7.3 / 10.3 / 15.3 | 17.3 / 17.0 / 17.1 |

- No click ripple: it is motion that ignores the "reduce motion" setting.

## Customizing

Colours come from the MGS semantic tokens. Override them in your app's stylesheet, never `.rs-*` / `.mgs-*` classes or
`--rs-*` variables:

```css
:root {
  --mgs-color-primary: #2563eb;
  --mgs-color-primary-hover: #1d4ed8;
  --mgs-color-primary-active: #1e40af; /* pressed */
  --mgs-color-focus-ring: #2563eb;
}
```

See `ARCHITECTURE.md` → Styling for the full token list and how themes work.
