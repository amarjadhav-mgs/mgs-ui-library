# MgsProvider

Sets the colour theme and the locale for every MGS component. Wrap the application in one `MgsProvider`, at its
root. The locale sets the language of built-in texts and the date and time formats, so every date in the app looks the
same.

**Component:** MGS-owned, built on RSuite 6.2.4 `CustomProvider` · Related:
[DatePicker](?path=/docs/components-date-time-datepicker--docs), [TimePicker](?path=/docs/components-date-time-timepicker--docs)

## When to use

- Once, at the root of every application that uses `@mgs/ui`.
- **Not around parts of a page.** The theme applies to the whole page, so a second provider with a different theme
  changes the page for everyone.
- ⚠️ **One theme per page.** Don't theme a single section with `data-theme`: popups (date pickers, menus, dialogs,
  toasts) open at the end of `<body>`, outside the section, so they keep the page's theme; and a light section inside
  a dark page isn't supported.

## Import

```tsx
import { MgsProvider } from '@mgs/ui';
import '@mgs/ui/styles.css'; // once, in your app entry
```

## Usage

```tsx
<MgsProvider theme="light" locale="en-GB">
  <App />
</MgsProvider>
```

Both props are optional: the defaults are `theme="light"` and `locale="en-GB"`.

The same inputs in each locale:

| `locale`          | Date         | Time                 | Week starts on | Numbers        |
| ----------------- | ------------ | -------------------- | -------------- | -------------- |
| `en-GB` (default) | `dd/MM/yyyy` | `HH:mm` (24-hour)    | Monday         | `1,234,567.50` |
| `en-US`           | `MM/dd/yyyy` | `hh:mm aa` (12-hour) | Sunday         | `1,234,567.50` |
| `en-IN`           | `dd/MM/yyyy` | `HH:mm` (24-hour)    | Monday         | `12,34,567.50` |

Numbers are formatted by [NumberInput](?path=/docs/components-numberinput--docs) (and later tables) with `Intl`, so
`en-IN` groups in lakhs and crores.

A component's own `format` prop still wins over the locale, but prefer the locale: one format for the whole app.

### Themes

| `theme`           | Use it for                                                          |
| ----------------- | ------------------------------------------------------------------- |
| `light` (default) | The standard MGS look                                               |
| `dark`            | Users who prefer a dark interface                                   |
| `high-contrast`   | Users with low vision (yellow on black); offer it as a user setting |

Switch the theme with the **Theme** button in the Storybook toolbar: it is this prop on Storybook's own provider.

### Server rendering (Next.js)

The provider sets the theme on `<body>` when the page runs in the browser, so a server-rendered page in a dark theme
would flash light until then. Set the same theme as `data-theme` on `<html>` on the server, too:

```tsx
// app/layout.tsx
import { MgsProvider } from '@mgs/ui';
import '@mgs/ui/styles.css';

export default async function RootLayout({ children }: { children: React.ReactNode }) {
  const theme = await getUserTheme(); // e.g. from a cookie: 'light' | 'dark' | 'high-contrast'
  return (
    <html lang="en-GB" data-theme={theme}>
      <body>
        <MgsProvider theme={theme}>{children}</MgsProvider>
      </body>
    </html>
  );
}
```

`@mgs/ui` components are client components (`'use client'`), so they work in Server Component pages and layouts.

### Common usage

- **App entry:** wrap the root component, next to the `@mgs/ui/styles.css` import.
- **User settings:** keep the theme and locale in the user's settings and pass them to the provider; changing them
  updates the whole app at once.
- **Dark mode from the system:** use `matchMedia('(prefers-color-scheme: dark)')` to pick `dark` when the user hasn't
  chosen a theme.

## Do and don't

| Do                                                       | Don't                                                               |
| -------------------------------------------------------- | ------------------------------------------------------------------- |
| Render one `MgsProvider` at the root of the app          | Nest providers with different themes                                |
| Choose the locale once, for the whole app                | Set a different `format` on each date picker                        |
| Set `<html lang>` to match the locale (`en-GB`, `en-IN`) | Leave `<html lang>` unset: screen readers need it to pronounce text |
| Offer `high-contrast` as a user setting                  | Use `high-contrast` as a brand look                                 |

## Accessibility

<Canvas of={MgsProviderStories.Accessibility} sourceState="shown" />

- The provider adds no element around your app: focus order, names and keyboard behaviour come from the components
  inside it. RSuite adds empty containers for toasts and dialogs at the end of `<body>`.
- When the last provider unmounts, it removes the theme class from `<body>`.
- `high-contrast` is an accessibility theme; every MGS colour pair meets WCAG AA in all three themes.
- It turns off RSuite's click ripple animation. With the system's "reduce motion" setting on, MGS and RSuite
  components stop animating transitions, and spinners turn more slowly.
- Icons need no inline `<style>` tag, so apps with a strict Content Security Policy (`style-src` without
  `'unsafe-inline'`) work: their styles ship in `@mgs/ui/styles.css`.
- ⚠️ **Set `<html lang>` yourself** to match the locale. The provider changes the texts and formats, not the page
  language that screen readers use.
