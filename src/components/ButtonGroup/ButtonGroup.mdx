# ButtonGroup

Joins buttons that belong together into one block: a view switcher, a set of related actions. It works with
[Button](?path=/docs/components-button--docs) and [IconButton](?path=/docs/components-iconbutton--docs).

**Component:** MGS-owned, built on RSuite 6.2.4 `ButtonGroup` · Related:
[Stack](?path=/docs/components-stack--docs) (buttons in a row with space between them)

## When to use

- For 2 to about 5 buttons that are one thing to the user: List / Board / Calendar, or Copy / Download / Delete.
- **Not for buttons that only stand next to each other** (Cancel and Save). Use a
  [Stack](?path=/docs/components-stack--docs) with `direction="row"`.
- **Not for choosing a value in a form.** Use radio buttons or a select: a group of buttons is not a form field.
- **Not for navigation between pages.** Use tabs or links.

## Import

```tsx
import { Button, ButtonGroup } from '@mgs/ui';
```

## Usage

```tsx
<ButtonGroup aria-label="View">
  <Button>List</Button>
  <Button>Board</Button>
</ButtonGroup>
```

⚠️ **Name the group** with `aria-label` or `aria-labelledby`, so screen readers say what the buttons are for. A
warning in the console tells you when the name is missing.

`orientation="vertical"` puts the buttons under each other. `fullWidth` fills the container with buttons of equal

### Advanced examples

<Canvas of={ButtonGroupStories.Advanced} sourceState="shown" />

A view switcher: the app keeps which button is chosen, shows it with the `primary` variant, and says it to screen
readers with `aria-pressed`. In a toolbar, a [Stack](?path=/docs/components-stack--docs) with `role="toolbar"` puts
space between groups and single buttons.

### Common usage

- **View switchers and filters with a few fixed values:** `aria-pressed` on each button, one of them `true`.
- **Row actions and toolbars:** icon buttons in a group, each with an `aria-label`.
- **Narrow screens:** `fullWidth`, or `orientation="vertical"` when the labels are long.

## Do and don't

| Do                                                       | Don't                                              |
| -------------------------------------------------------- | -------------------------------------------------- |
| Group buttons that are one thing to the user             | Group Cancel and Save: they are separate actions   |
| Name the group with `aria-label`                         | Leave the group without a name                     |
| Use one variant and one size in a group                  | Mix primary, danger and ghost buttons in one group |
| Show the chosen button with `aria-pressed` and a variant | Show the chosen button by colour alone             |
| Keep the labels short                                    | Put more than about 5 buttons in a group           |

## Accessibility

<Canvas of={ButtonGroupStories.Accessibility} sourceState="shown" />

| Key               | Action                                                        |
| ----------------- | ------------------------------------------------------------- |
| `Tab` / `⇧ Tab`   | Move to the next / previous button, skipping disabled buttons |
| `Enter` / `Space` | Press the focused button                                      |

- Renders `role="group"`: screen readers announce the group's name when the user enters it.
- Each button is a Tab stop; there are no arrow keys.
- The focus ring of a button is drawn above its neighbours, so no part of it is covered.
