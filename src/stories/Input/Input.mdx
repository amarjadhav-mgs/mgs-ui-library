# Input

`Input`, `InputGroup`, `Textarea` and `PasswordInput` from **`@mgs/ui`**: single-line and multi-line text fields,
optionally with add-ons (text, icons, buttons). This page shows which props exist, when to use them, and what to
watch out for.

## Setup

```tsx
// Once, in your app entry
import '@mgs/ui/styles.css';

// Anywhere
import { Input, InputGroup, Textarea, PasswordInput } from '@mgs/ui';
```

`@mgs/ui` components are [RSuite 6](https://rsuitejs.com/components/input) components with the MGS theme, so
RSuite's documentation applies to every prop.

## Always label inputs

Input has **no `label` prop**. Every field needs a visible `<label htmlFor>` connected to the input's `id`, or, when a
visible label really isn't possible (a search box with an icon), an `aria-label`. A placeholder is **not** a label:
it disappears as soon as the user types. The accessibility tests on these stories fail if a field has no label.

```tsx
<label htmlFor="email">Email</label>
<Input id="email" type="email" />
```

## Basic

<Canvas of={InputStories.Basic} sourceState="shown" />

Set the right `type` (`email`, `tel`, `url`, `search`...) so mobile keyboards and browser autofill work, and a `name`
for forms. All native input attributes work (`autoComplete`, `maxLength`, `required`, `aria-*`, ...).

## Sizes

<Canvas of={InputStories.Sizes} sourceState="shown" />

`size`: `lg | md` (default) `| sm | xs`. Use the same size as the buttons next to the field. Inside an `InputGroup`,
set `size` on the group.

⚠️ The `size` type also accepts `"xl"`, but RSuite has no `xl` input styles, so it renders like `md`. Don't use it.

## Width

Inputs, textareas and input groups are **full width by default**: they fill their container (there's no `block`
prop, because it's already the default). Control the width with the layout, e.g. a `maxWidth` on the form or a grid
column, so fields adapt on small screens. There are no responsive size props; keep the same `size` and let the
container change.

## Disabled / Read-only / Plaintext

<Canvas of={InputStories.States} sourceState="shown" />

| Prop        | Focusable | Editable | Submitted with a form | Use it for                                   |
| ----------- | --------- | -------- | --------------------- | -------------------------------------------- |
| `disabled`  | No        | No       | No                    | Fields that don't apply right now            |
| `readOnly`  | Yes       | No       | Yes                   | Values users should see and copy, not change |
| `plaintext` | No        | No       | No (no input at all)  | Read-only "view" pages showing saved values  |

Prefer `readOnly` over `disabled` for values users need to read: disabled text is low contrast and skipped by
keyboard users.

## Controlled

<Canvas of={InputStories.Controlled} sourceState="shown" />

⚠️ **`onChange` receives the value first**: `onChange(value, event)`, not `onChange(event)` like a native input. Write
`onChange={(value) => setName(value)}` (or `onChange={setName}`).

## InputGroup

<Canvas of={InputStories.InputGroups} sourceState="shown" />

- `InputGroup.Addon` holds text or an icon (units, prefixes, a search icon).
- `InputGroup.Button` holds a button (Search, Copy).
- `inside` places add-ons inside the input's border.
- `size` and `disabled` on the group apply to everything in it.

The input still needs its own label; add-on text like "https://" doesn't label the field.

## Clear button

<Canvas of={InputStories.Clearable} sourceState="shown" />

RSuite's Input has **no built-in clear button**. For search and filter fields, add one with `InputGroup inside` and
`InputGroup.Button`, as shown:

- Give the button an `aria-label` ("Clear search"); the icon alone has no name.
- Show it only when there's text.
- After clearing, **move focus back to the input** (`inputRef.current?.focus()`), otherwise keyboard focus is lost
  when the button disappears.

## Textarea

<Canvas of={InputStories.TextareaStory} sourceState="shown" />

For multi-line text. Use `rows` for a fixed height, or `autosize` with `minRows` / `maxRows` to grow with the
content. `resize` controls whether users can drag the size. Same labelling rules as Input.

## PasswordInput

<Canvas of={InputStories.Password} sourceState="shown" />

A password field with a show/hide button. ⚠️ **Limitations** (RSuite 6.2):

- **Label it with `<label htmlFor>` + `id`.** `aria-label`, `aria-describedby`, `aria-invalid`, `required` and
  `disabled` go to the wrapper, not the input, so they don't work.
- **The show/hide button can't be reached with Tab** (it has `tabIndex={-1}`), so keyboard users can't reveal the
  password. Its label is always English ("Toggle password visibility").
- It sets `autoComplete="off"`, which you can't change.

For **login and sign-up forms**, where error messages and password managers matter, use a plain password input
instead:

```tsx
<label htmlFor="password">Password</label>
<Input
  id="password"
  type="password"
  autoComplete="current-password" // "new-password" on sign-up
  aria-invalid={Boolean(error)}
  aria-describedby={error ? 'password-error' : undefined}
/>
```

## Validation

<Canvas of={InputStories.Validation} sourceState="shown" />

Show the error **as text** under the field, link it with `aria-describedby`, and set `aria-invalid` so screen readers
announce it. Don't rely on a red border alone. Validate on submit or on blur, not on every keystroke.

## Accessibility

<Canvas of={InputStories.Accessibility} sourceState="shown" />

| Key             | Action                                      |
| --------------- | ------------------------------------------- |
| `Tab` / `⇧ Tab` | Move to the next / previous field           |
| `Enter`         | Calls `onPressEnter` (e.g. submit a search) |

- Every field has a label (see [Always label inputs](#always-label-inputs)).
- The focus ring uses `outline` and is fully visible with the MGS theme.
- The MGS theme darkens input borders so fields are visible (WCAG 1.4.11 needs 3:1). RSuite's default border is
  1.3:1 in light mode and 1.6:1 in dark mode. The theme uses 3.1:1 (light) and 3.3:1 (dark); high contrast is
  unchanged (10.7:1).
- Placeholder text meets contrast (4.8:1), but it's still not a label.

## Customizing

Override RSuite's `--rs-*` CSS variables in your app's stylesheet, never `.rs-input` properties. For one-off layout
tweaks use `className` or `style`.
